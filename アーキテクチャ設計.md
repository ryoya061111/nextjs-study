# React/Next.js学習プロジェクト - アーキテクチャ設計

## プロジェクト概要

学習用フロントエンドWebアプリケーション。Next.js + React + TypeScript（SSR）を使用した、TODO CRUD機能を持つアプリケーション。

### プロジェクト要件

| 項目 | 内容 |
|------|------|
| フロントエンド | Next.js、React、TypeScript、SSR |
| 状態管理 | Context API + Hooks（※TanStack Queryは後対応） |
| フォーム管理 | React Hook Form + Zod |
| API連携 | 純粋関数モック実装（※MSWは後対応） |
| 主要機能 | TODO CRUD、ログイン管理（モック） |
| 対象学習者 | React初心者〜中級者 |


### 2. コンポーネントレイヤー（Components）

**役割**：再利用可能なUI部品の実装

**分類**：
- **UI Components**：汎用的なボタン、入力欄など（`components/ui/`）
- **Feature Components**：機能別のコンポーネント（`components/auth/`, `components/todos/`）
- **Layout Components**：レイアウト構成用（`components/common/`）

**学習ポイント**：
- React 関数型コンポーネント
- Props による親子通信
- 状態のリフティング（State Lifting）
- コンポーネント設計パターン

**例**：
```typescript
// components/todos/TodoItem.tsx
interface Props {
  todo: Todo
  onDelete: (id: string) => void
  onEdit: (id: string) => void
}

export const TodoItem: React.FC<Props> = ({ todo, onDelete, onEdit }) => {
  return (
    <div className="todo-item">
      <h3>{todo.title}</h3>
      <button onClick={() => onEdit(todo.id)}>編集</button>
      <button onClick={() => onDelete(todo.id)}>削除</button>
    </div>
  )
}
```

### 3. カスタムフックレイヤー（Hooks）

**役割**：ロジックの再利用と状態管理

**主要フック**：
- `useAuth()` ：認証状態とログイン/ログアウト処理
- `useTodos()` ：TODO一覧取得、作成、編集、削除
- `useFetch()` ：汎用API呼び出しロジック
- `useLocalStorage()` ：ブラウザストレージ操作

**学習ポイント**：
- `useState` による状態管理
- `useEffect` による副作用処理
- 依存配列の理解
- カスタムフック作成パターン
- 非同期処理（async/await）

**例**：
```typescript
// hooks/useTodos.ts
export const useTodos = () => {
  const [todos, setTodos] = useState<Todo[]>([])
  const [loading, setLoading] = useState(false)
  const [error, setError] = useState<string | null>(null)

  // TODO取得
  const fetchTodos = useCallback(async () => {
    setLoading(true)
    try {
      const data = await todoService.getTodos()
      setTodos(data)
    } catch (err) {
      setError(err instanceof Error ? err.message : 'エラーが発生しました')
    } finally {
      setLoading(false)
    }
  }, [])

  // TODO作成
  const createTodo = useCallback(async (title: string) => {
    // 実装
  }, [])

  return { todos, loading, error, fetchTodos, createTodo }
}
```

### 4. Contextレイヤー（Context API）

**役割**：アプリケーション全体の共有状態管理

**グローバル状態**：
- ユーザー認証情報（ユーザー、トークン、ログイン状態）
- TODO一覧（全ページで参照する必要がある場合）

**学習ポイント**：
- `useContext` による状態共有
- Context Provider の設計
- 不要な再レンダリングの最適化

**例**：
```typescript
// context/AuthContext.tsx
interface AuthContextType {
  user: User | null
  isLoggedIn: boolean
  login: (email: string, password: string) => Promise<void>
  logout: () => void
}

export const AuthContext = createContext<AuthContextType | undefined>(undefined)

export const AuthProvider: React.FC<{ children: React.ReactNode }> = ({ children }) => {
  const [user, setUser] = useState<User | null>(null)

  const value = {
    user,
    isLoggedIn: !!user,
    login: async (email, password) => {
      // ログイン処理
    },
    logout: () => {
      // ログアウト処理
    }
  }

  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>
}
```

- モックデータの提供

**学習ポイント**：
- Promise と async/await
- HTTP通信（GET, POST, PUT, DELETE）

**例**：
```typescript
// services/todoService.ts
export const todoService = {
  // TODO一覧を取得
  getTodos: async (): Promise<Todo[]> => {
    const response = await fetch('/api/todos')
    if (!response.ok) throw new Error('取得に失敗しました')
    return response.json()

  // TODOを作成

    const response = await fetch('/api/todos', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ title })
    })
    if (!response.ok) throw new Error('作成に失敗しました')
    return response.json()
  },

  // TODO更新
  updateTodo: async (id: string, title: string): Promise<Todo> => {
    // 実装
  },

  // TODO削除
  deleteTodo: async (id: string): Promise<void> => {
    // 実装
  }
}
```

### ページ初期表示フロー（SSR）

```

    ▼ HTTPリクエスト

│    │           └── Todo[] 返却              │
│    │                                        │
│    └── <TodoList initialTodos={todos} />    │
│          ↓ HTML生成（初期データ埋め込み）    │
└─────────────────────────────────────────────┘
    │
    ▼ HTML返却（データ込み）
┌─────────────────────────────────────────────┐
```

### TODO作成フロー（CSR）

```
ユーザーが「新規作成」ボタンをクリック
    │
    ▼ [ブラウザ / Client Component]
TodoList.tsx
    │ showForm = true → TodoForm表示
    ▼
TodoForm.tsx（React Hook Form + Zod）
    │ 入力・バリデーション
    │ handleSubmit → onSubmit(data)
    ▼
useTodos.ts → createTodo(data)
    │
    └── todoService.ts → fetch('POST /api/todos', data)
              │
              ▼ HTTPリクエスト
    ┌─────────────────────────────────┐
    │  Node.js ランタイム              │
    │  app/api/todos/route.ts         │
    │    └── mockData.push(newTodo)   │
    │    └── return 201 + newTodo     │
    └─────────────────────────────────┘
              │
              ▼ レスポンス（新しいTodo）
useTodos.ts → setTodos([...todos, newTodo])
    │
    ▼ 再レンダリング
TodoList.tsx → 新しい項目が一覧に表示される
```

```
ユーザーが「編集」ボタンをクリック
    │
    ▼ [ブラウザ]
Link → /todos/[id]/edit に遷移
    │
    ▼ HTTPリクエスト
┌─────────────────────────────────────────────┐
│  Node.js ランタイム                          │
│                                             │
│  [id]/edit/page.tsx（Server Component）      │
│    │                                        │
│    ├── todoRepository.getById(id)            │
│    │     └── mockData.ts ← 該当Todoを返す   │
│    │                                        │
│    └── <TodoEditForm todo={todo} />         │
│          ↓ HTML生成（既存データ埋め込み）    │
└─────────────────────────────────────────────┘
    │
    ▼ HTML返却
TodoEditForm.tsx（Client Component）
    │ TodoForm に defaultValues として渡す
    │ ユーザーが編集・送信
    └── todoService.update(id, data)
              │
              ▼ fetch('PUT /api/todos/[id]')
    ┌─────────────────────────────────┐
    │  app/api/todos/[id]/route.ts    │
    │    └── mockData[index] 更新     │
    └─────────────────────────────────┘
              │
              ▼
router.push('/todos') + router.refresh()
    → /todos に戻り、一覧を再取得
```

```
    │    └── return 204 No Content    │
    └─────────────────────────────────┘
              │
              ▼
useTodos.ts → setTodos(todos.filter(t => t.id !== id))
    │
    ▼ 再レンダリング
TodoList.tsx → 削除した項目が消える
```

### 認証フロー（ログイン）

```
ユーザー入力
    ↓
[LoginForm コンポーネント（React Hook Form + Zod）]
    ↓ (submit)
[Auth.js signIn()]
    ↓ (POST /api/auth/[...nextauth])
[Next.js API Route / Auth.js ハンドラ]
    ↓ (モック認証処理)
[JWT生成]
    ↓
[HttpOnly Cookie に保存]  ← ※localStorageは使わない（XSS対策）
    ↓
[AuthContext状態更新]
    ↓
[ページリダイレクト → ダッシュボード]
```

### ページレンダリングフロー（SSR）

```
ユーザーがURLアクセス
    ↓
[Next.js Server]
    ↓ (page.tsx実行)
[サーバーコンポーネント]
    ↓ (データ取得)
[データベース/API]
    ↓ (HTML生成)
[Server → Client]
    ↓
[ブラウザで表示]
    ↓ (Hydration)
[クライアント側でインタラクティブ化]
```

## コーディングルール

### 1. コメント規則（初心者向け）

```typescript
// React 関数型コンポーネント：この構文は React 18 以降の標準形式です
export const MyComponent: React.FC<Props> = ({ prop1, prop2 }) => {
  // useState の構文：状態 = [現在の値, 値を更新する関数] = useState(初期値)
  const [count, setCount] = useState(0)

  // useEffect の構文：副作用（データ取得など）を定義します
  // 第2引数の依存配列 [] は、このコンポーネントがマウントされた時のみ実行
  useEffect(() => {
    // ここにデータ取得などの処理を書きます
    fetchData()
  }, [])

  return <div>...</div>
}
```

### 2. ネーミング規則

- **コンポーネント**：PascalCase（例：`TodoItem`, `LoginForm`）
- **関数/変数**：camelCase（例：`getTodos`, `isLoading`）
- **定数**：UPPER_SNAKE_CASE（例：`MAX_TITLE_LENGTH`, `API_BASE_URL`）
- **型/Interface**：PascalCase（例：`Todo`, `User`）
- **ファイル**：
  - コンポーネント：PascalCase（`TodoItem.tsx`）
  - その他：camelCase（`todoService.ts`, `useAuth.ts`）

### 3. 型定義ルール

```typescript
// すべてのコンポーネント Props に型を付与
interface TodoItemProps {
  todo: Todo
  onDelete: (id: string) => void
}

// API レスポンスに型を付与
interface ApiResponse<T> {
  data: T
  error: string | null
  status: number
}

// 関数の引数と戻り値に型を付与
const getTodos = async (userId: string): Promise<Todo[]> => {
  // 実装
}
```

### 4. TODO機能の CRUD 実装

```typescript
// Create：新規作成
const createTodo = async (title: string): Promise<Todo> => {}

// Read：取得
const getTodos = async (): Promise<Todo[]> => {}
const getTodoById = async (id: string): Promise<Todo> => {}

// Update：更新
const updateTodo = async (id: string, updates: Partial<Todo>): Promise<Todo> => {}

// Delete：削除
const deleteTodo = async (id: string): Promise<void> => {}
```

## 注意事項

- **モックデータ**：現在はAPI Routesにモックデータを返すようにします。将来的にバックエンドを追加する場合は、serviceレイヤーの実装を変更するだけで対応可能です。

- **SSR vs CSR**：このプロジェクトではSSRを活用しますが、個別のコンポーネントはクライアント側で インタラクティブに動作します。

- **スタイリング**：Tailwind CSSの使用はオプションです。必要に応じてCSS Modulesなどの他のソリューションも検討してください。
